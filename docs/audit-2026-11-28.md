# Senior audit remediation — 28/11/2026

The attached remediation prompt (`Lnf_Ai_Fix_Prompt.md`) lists 40 findings against base commit
`f6b19a6`. This is what happened to each: fixed here, already fixed, or disputed. Every claim was
checked against the code before anything was changed.

## Fixed in migration 0022 (numbered 0022, not 0020 — 0020 and 0021 are taken)

| Finding | What was wrong | Fix |
| --- | --- | --- |
| **Handover codes came from `random()`** | a bearer token generated by a non-cryptographic PRNG; predictable if the seed leaks | `extensions.gen_random_bytes(1)` per character |
| `staff_decide_claim` could be raced | the item was locked, the claim was not | `FOR UPDATE` on both, before the reads |
| Handover code never expired in the check | `expires_at` existed but was never enforced | `CODE_EXPIRED` returned |
| `code_plain` survived a handover | a spent code stayed readable in the row | nulled on use and on the remaining codes of that claim |
| Quarantined stub returned `id` | an internal uuid for a document that must not be described | stub is `ref`, `type`, `status` only |
| `saved_items` writable directly | writes should go through `toggle_saved_item()` | insert/delete revoked |
| Photo path not bound to the uploader | a user could reference another user's object path | policy requires the first path segment to be `auth.uid()` and forbids `..` |
| `auto_hide_photos` ignored | the per-category flag was never read | `create_item` now ORs it into `sensitive_hidden_photo` |
| "Today" was UTC | a report filed at 02:00 IST could be dated yesterday | compared against `now() at time zone 'Asia/Kolkata'` |
| `log_auth_event` unthrottled | a free way to fill a table | 30 / 15 min per address hash |
| Claim drafts skipped the throttle when no IP | hiding the header bypassed the bucket | falls back to `anon-global`, plus a per-email bucket |
| `finalise_claim_draft` trusted the session | any verified session could finish someone else's draft | the JWT email must match the draft email (`EMAIL_MISMATCH`) |
| Duplicate claims raised a raw error | unique violation surfaced as a 500 | caught, returns `ALREADY_CLAIMED` |
| Outbox rows stuck in `sending` | a crashed run left them unrecoverable | `claim_email_batch` now reclaims `pending` **and** `sending` |
| Audit chain could not verify after retention | the oldest row's `prev_hash` pointed at a deleted row | the first retained row is the anchor |
| Missing invariants | nothing stopped two approved claims or two handovers on one item | five unique indexes |
| Storage deletions had no durable record | photo paths were returned and lost | `storage_deletion_queue` (service-role only) |

# The external hardening patch (28/11, later)

`lnf-full-hardening.patch` (116 KB) was written against an older commit and creates
`supabase/migrations/0020_audit_remediation.sql` and `0021_deep_hardening.sql`. Both numbers are
already taken here (chat, bulk import), and 20 of its 38 files have moved since. `git apply`
fails on 11 files, so applying it would have regressed the chat, the importer and the previous
remediation.

What I did instead: read every hunk, keep what is genuinely better, port it as `0023`, verify each
piece against the live database.

## Ported

| Change | Why it is better |
| --- | --- |
| `scan_message` phone pattern | it missed `+91 98765 43210` and `98765-43210` — a split number is exactly how a scammer writes it |
| `scan_message` PAN pattern | case-insensitive and boundary-anchored; `pan abcde1234f` slipped through before |
| `create_found_item_anonymous` | default date in IST, and an empty IP now falls back to `anon-global` instead of skipping the throttle |
| `queue_email_retry` | event-type allowlist plus 10/hour; it accepted any event name and had no limit |
| `request_account_deletion()` | erasure goes through an RPC with a rate limit and duplicate check, instead of a raw table insert from the browser |
| `notifications` UPDATE | column-scoped to `read_at`; the owner could rewrite the body |
| `saved_searches` / `abuse_reports` writes | revoked; the RPCs are the only writers |
| `has_role()` | internal predicate, no longer executable by clients |
| `src/lib/client-photo.ts` | compresses photos on the phone before upload |

That last one is the most useful thing in the patch, and it corrects a mistake of mine: I raised
`serverActions.bodySizeLimit` to 16 MB, but **Vercel rejects request bodies over ~4.5 MB before
the action runs**, so the setting could never help. Compression on the client is the fix that
actually works, and it also cuts Supabase Storage use.

Verified after porting: `98765 43210`, `+91-98765-43210` and `abcde1234f` are all caught;
`found near the library gate` is not; `notifications.read_at` is updatable and nothing else is;
`saved_searches` insert is refused.

## Deliberately not ported

**Revoking execute on `check_signin_allowed()` and `log_auth_event()` from `anon`.** Our sign-in
path calls both with the visitor's session *before* an account exists. Revoking them breaks
sign-in entirely — and those two functions are the throttle protecting the form. The patch may
have moved those calls to a service-role client; we did not, and the anon grant is what makes the
flow work.

## Still open from that patch

`admin_erase_user_data()` (the patch does not implement it either — it only adds the request RPC),
the storage-queue cron drain, the dark-mode `@media` mirror, `React.cache`, and age-encrypted
backups. Same reasons as above.
