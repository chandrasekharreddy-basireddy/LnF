# Audit of the audit — `multi_agent_master_audit_upgrade_blueprint.md`

Reviewed 26/11/2026 against commit `f538168` (96 files, 26 routes, 9 migrations).
Every verdict below was produced by reading this repository, not by trusting the blueprint.

## Bottom line

The blueprint is a competent wish-list with a credible threat model, and its *security*
instincts are good — four of the six real defects it points at were genuinely present here.

It is not, however, an accurate audit of this codebase. Of its twelve stated "gaps", six do not
exist in this repo, and two of its recommendations would break the product if implemented as
written. Its dependency advice is already satisfied, and its orchestration layer (7 agents,
6 waves, file-lock matrix) costs more in merge conflicts than it saves on a 96-file codebase.

I fixed the six defects that were real. Everything else is a decision for you, listed at the end
with sizes.

## What it got wrong

| Blueprint claim | Reality | Why it matters |
| --- | --- | --- |
| "Migrations `0001`–`0007`; start additive work at `0008_security_hardening.sql`" | Nine migrations exist; `0008_role_bootstrap.sql` was already taken | following the plan verbatim collides on a filename and skips a migration it never read |
| "Upgrade `next` to `>= 16.3.3` to patch GHSA-2xp9-vwfh-vxw4 and CVE-2026-75604" | Installed `next` is 16.4.6; `npm audit --audit-level=high` reports 0 vulnerabilities | advice already satisfied — no action needed |
| "This app is exposed to the AVIF image-optimisation RCE" | `next/image` is never used; photos are plain `<img>` with short-lived signed URLs, so `/_next/image` is unreachable | the attack surface the plan spends a section on does not exist here |
| "`verification_question` must not be readable by `anon`" | it is public by design — it is the prompt the claimant answers; only `answer_hash` is private | implementing this removes the question from the item page and makes claims impossible |
| "Flag `SECURITY DEFINER` functions missing `SET search_path`" | all 23 such functions already set `search_path` | the audit item is a no-op |
| "Every `INSERT`/`UPDATE` policy needs `WITH CHECK`" | all four write policies already have one (22 policies total; the rest are SELECT/DELETE) | no-op |
| "Add a `handovers` table" | `handover_codes` + `handover_records` already cover issue, verify, lock and audit | a third table fragments the one flow that must stay atomic |
| "Add `sensitive_hidden_photo` / `expires_at` columns to items" | both exist | would fail as written |
| "CVE-2026-75604 is critical for this deployment" | real CVE, but Windows-filesystem only; Vercel runs Linux | mislabels the risk level of the deployment |
| "`npm run lint` must exit 0" | there is no lint script and no ESLint config in the repo | a gate that cannot run is not a gate |

## Where the plan would make the product worse

1. **Hiding the verification question** (above) — kills the claim flow.
2. **`FORCE ROW LEVEL SECURITY` everywhere** — the tables are owned by `postgres` and every client
   connects as `anon`/`authenticated`, so FORCE changes nothing except making the service-role
   housekeeping job fail. Worth adding per-table only where a table owner is also an app role.
3. **`localStorage` draft autosave in the report wizard** — a lost phone's draft would contain the
   verification answer in plaintext on the device. The answer is currently only ever sent once.
4. **Storing claim proofs (ID photos) in a new bucket** — the product rule is that ID documents are
   never photographed or uploaded; the desk checks them in person. Adding an upload path quietly
   reverses a promise the privacy page makes.

## Follow-up: the five upgrades, shipped

Built in the order recommended above, each verified before the next.

| # | Item | What landed | How it is checked |
| --- | --- | --- | --- |
| 1 | CSP | `src/proxy.ts` mints a per-request nonce; strict policy on request and response; the file moved from `middleware.ts` because Next 16 renamed the convention | smoke asserts the header, the nonce, and that a `<script>` carries it |
| 2 | ESLint | flat config (typescript-eslint, react-hooks, jsx-a11y, no `any`), `npm run lint` first in CI; TypeScript pinned to 5.9 because typescript-eslint cannot parse TS 7, ESLint to 9 because jsx-a11y does not support 10 | CI `verify` job |
| 3 | Playwright + axe | 39 tests over 360/768/1440, two specs, against the mock; axe bypasses CSP to inject, the CSP itself is asserted in smoke | CI `e2e` job, 37 passed / 2 viewport skips |
| 4 | Skeletons | `loading.tsx` for browse, item, claims, claim, staff, admin, account | build + e2e navigation |
| 5 | Email outbox | migration `0010`, `sendOrQueue`, 3-attempt retry with dedupe key and a 5-minute lease, drained by the cron | SQL privilege checks + typecheck; the send path is not exercised end to end here |

Three defects surfaced while building these, all fixed:

1. **The header sign-in button was white on white.** `.nav a` sets `background: none` and
   outranks `.btn`, so the button rendered at 1.02:1. Axe flagged it on every route.
2. **`--ink-mute` measured 4.34:1** on the paper background, under the AA floor for body text.
   Darkened to `#64726c` (4.86:1).
3. **The tablet project ran on WebKit** because `devices['iPad Mini']` pins that browser while
   CI installs Chromium only; every tablet test failed in 2 ms.

Nothing from the recommended list is still open. The larger features (masked claim messaging,
saved searches, disposal queue, QR labels, the editorial UI overhaul) remain deliberately
unbuilt.
