## Verified and deliberately not changed

| Finding | Why it stands |
| --- | --- |
| `to_public_item()` is `SECURITY DEFINER`-adjacent and callable | it is now service-role only; every caller is already definer-scoped |
| Migrations `0001`–`0004` are not re-runnable (the sample seed would duplicate) | they are an ordered history; re-running a history file is not a supported operation. `0014` is idempotent |
| A `claimed` item can still be archived by a staff status change | staff action, audited; blocking it would stop the desk recovering from a mis-click |
| `handover_codes.code_plain` is stored in the row | deliberate: the claimant must be able to read the code once. It is hashed for verification and single-use |
| The mock returns `signedURL` | correct: `@supabase/storage-js` maps `signedURL` to `signedUrl` in the client |

## Closed in the follow-up pass

Everything that was open, plus the findings I had filed as "acceptable".

| Finding | Fix |
| --- | --- |
| Staff actions reported "try again" after a committed write, because the follow-up email sat inside the same `try` | the write decides the result; the email and cache refresh are best effort in `notifyClaimant()` / `thankFinder()` |
| A status change or disposal could archive an item with an approved claim waiting to be collected | both refuse with `HAS_APPROVED_CLAIM` (migration `0015`) |
| Sequences were usable by `authenticated`, so a reference number could be burned with `nextval()` | usage and select revoked |
| Re-running the `0004` seed would duplicate the sample board | the insert is now guarded on `not exists (select 1 from items where is_sample)` |
| The claim email passed the item reference as if it were a title | copy now says "for item LF-2026-…" |
| Saving the profile said "Saved." even when no row matched | `.select('id')` and an explicit empty-result error |
| Photo uploads over 1 MB failed before the action ran (Next's default body limit) | `serverActions.bodySizeLimit: '6mb'` |
| The theme cookie was not `secure` | set in production only |
| `/sitemap.xml` and `/robots.txt` bypassed the CSP entirely (the proxy matcher skips `.xml`/`.txt`) | a `default-src 'none'` baseline in `next.config.ts` for those paths |
| `searchItems()` returned an empty list when the database was unreachable, so a broken board looked like an empty one | returns `ok: false`, and `/browse` shows "the board did not load — this is not an empty board" |
| `currentUser()` swallowed a failed role lookup, so a database blip read as "no staff access" | `roleCheckFailed` on the session, and `/staff` and `/admin` say "we could not check your access" instead of refusing |
| Lower-case handover codes were not recognised by the scanner | `extractCode()` upper-cases before matching — found by a unit test, not by reading |

### Tests added

`npm test` runs 33 unit tests over the logic that had none: `safeInternalPath` (including the
control-character and dot-segment bypasses), the antifraud scanner, `extractCode`, the email
templates (HTML escaping, every outbox event type) and the field validators. They run in CI
before typecheck.

Writing them found two more defects: the dot-segment normalisation above, and the
case-sensitivity bug in `extractCode`.

## Still open, by decision

1. **Claim proof attachments.** The blueprint wanted them in a private bucket. The product
   promises that ID documents are never uploaded or photographed — the desk checks them in
   person. Adding the upload path reverses that promise, so it needs a product decision, not a
   patch.
2. **No end-to-end test of an authenticated flow** (claim → decide → handover). The harness has
   no session, and faking one means teaching the mock the Supabase cookie format, which risks
   testing the fake rather than the app. Those paths are covered at SQL level and by the unit
   tests over their pure parts.
3. **`handover_codes.code_plain` stays in the row.** The claimant must be able to read the code
   once; it is hashed for verification and single-use. Removing the plaintext would mean
   showing it before it is stored, which the "show once, then never again" rule needs.
