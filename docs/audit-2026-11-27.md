## Open, not fixed (ranked)

1. **`staff_decide_claim` and `dispose_item` still have no confirmation dialog.** The reason field is optional on approve; a two-step confirm would be the right fix, but it is a UI decision, not a defect.
2. **`data.ts` cannot distinguish "empty board" from "database unreachable"** for most readers. `boardStats()` was fixed earlier; `searchItems()` still returns an empty list on error. A `{ ok, items }` shape would fix it and touch every caller.
3. **`currentUser()` swallows a failed role lookup**, so a database blip looks like "no staff access". Fixing it means the layout has to render an error state.
4. **Claim proofs are text only.** The blueprint wanted attachments in a private bucket; that reverses the "ID documents are never uploaded" promise and needs a product decision.
5. **No test covers an authenticated flow** (claim → decide → handover). The harness has no session, so those paths are verified at SQL level only.
6. **`theme` cookie is not `secure`.** Harmless on HTTPS-only hosting; set it when the domain is final.
7. **Sequence `USAGE` is still granted to `authenticated`.** A signed-in user could call `nextval()` and burn reference numbers. Low impact, one-line fix.

## Method note

Sub-agent summaries are self-reports. Two of the high findings were wrong in their specifics
(field name, blast radius) while pointing at something real nearby, which is the usual failure
mode: the location is right, the consequence is guessed. Everything above the "Not reproduced"
line was confirmed by reading the file or running the code.
